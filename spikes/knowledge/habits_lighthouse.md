# Review habits: sigp/lighthouse

What this repo's maintainers ask for again and again. From 3746 maintainer review threads in 672 PRs, first comment before 2026-04-24. Ranked by PRs, then maintainers. Each line: the habit (where; how often) "an example" source.

1. Update or delete comments, docs, book pages and TODOs the change made stale. (everywhere; 107 PRs, 13 maintainers) "Can delete this comment" [#7743](https://github.com/sigp/lighthouse/pull/7743)
2. Delete unused, commented-out, debug or speculative code, imports and dependencies. (everywhere; 97 PRs, 14 maintainers) "We can delete this function, it isn't used anywhere." [#4718](https://github.com/sigp/lighthouse/pull/4718)
3. Fix typos, grammar and punctuation. End comments with a period. Sentence-case logs. (everywhere; 80 PRs, 13 maintainers) "small typo `fork choice`" [#7805](https://github.com/sigp/lighthouse/pull/7805)
4. Comment non-obvious logic, return values and chosen constants. Keep useful existing comments. (`**/*.rs`; 62 PRs, 11 maintainers) "can we add a comment here for how we got 40?" [#8694](https://github.com/sigp/lighthouse/pull/8694)
5. Names must say exactly what a thing is. Rename when meaning changes. (`**/*.rs`; 61 PRs, 13 maintainers) "should this be called `advertised_custody_group_count`?" [#7578](https://github.com/sigp/lighthouse/pull/7578)
6. Prefer simple idiomatic Rust: combinators, early returns, derives, no redundant checks. (`**/*.rs`; 56 PRs, 11 maintainers) "Isn't this just `.insert`?" [#8339](https://github.com/sigp/lighthouse/pull/8339)
7. Reuse existing helpers and methods. Don't duplicate logic. (`**/*.rs`; 48 PRs, 12 maintainers) "I think this is already on EthSpec as `E::ptc_size()`" [#9145](https://github.com/sigp/lighthouse/pull/9145)
8. Add tests for new behaviour, untested paths and new CLI flags. (`**/*.rs`, `lighthouse/tests/**`; 40 PRs, 7 maintainers) "Needs a CLI test in `lighthouse/test/validator_client.rs`" [#7047](https://github.com/sigp/lighthouse/pull/7047)
9. Run cargo fmt, clippy and markdownlint. No `#[allow]` or wildcard imports. (everywhere; 38 PRs, 9 maintainers) "Please remove wildcard imports" [#7923](https://github.com/sigp/lighthouse/pull/7923)
10. Never drop errors silently. Log with context like `peer_id`, or propagate. (`**/*.rs`; 38 PRs, 7 maintainers) "should we at least log the store error here?" [#8247](https://github.com/sigp/lighthouse/pull/8247)
11. No `unwrap`, `expect`, `panic!` or `unreachable!` on reachable paths. Return an error. (`**/*.rs`; 37 PRs, 9 maintainers) "We should use errors here rather than unwrapping" [#5898](https://github.com/sigp/lighthouse/pull/5898)
12. Don't recompute or reload values. Do cheap checks before expensive work. (`**/*.rs`; 37 PRs, 9 maintainers) "wanna move this check to before build_all_caches ?" [#8998](https://github.com/sigp/lighthouse/pull/8998)
13. Avoid needless clones, allocations, `Arc` and locks. Borrow or use `Copy`. (`**/*.rs`; 34 PRs, 8 maintainers) "Is this `Arc` necessary?" [#7892](https://github.com/sigp/lighthouse/pull/7892)
14. Put code in the module that owns the data. Use the smallest visibility. (`**/*.rs`; 30 PRs, 10 maintainers) "this can be just `pub(crate)`:" [#9085](https://github.com/sigp/lighthouse/pull/9085)
15. Replace hardcoded numbers with named constants, spec values or config options. (`**/*.rs`; 27 PRs, 8 maintainers) "Why 8 and not LOW_VALIDATOR_COUNT?" [#7907](https://github.com/sigp/lighthouse/pull/7907)
16. Tag TODOs by feature, like `TODO(gloas)`, and link the tracking issue. (`**/*.rs`; 27 PRs, 6 maintainers) "Add `TODO(hdiff)`" [#7174](https://github.com/sigp/lighthouse/pull/7174)
17. Pick fitting log levels. Avoid noisy, duplicate or huge Debug logs. (`**/*.rs`; 23 PRs, 10 maintainers) "This debug here appears like it could become very noisy." [#5570](https://github.com/sigp/lighthouse/pull/5570)
18. Use fork helpers like `electra_enabled()`. Check `>=` versus `>` in fork comparisons. (`**/*.rs`; 23 PRs, 7 maintainers) "`fork.electra_enabled()`" [#5741](https://github.com/sigp/lighthouse/pull/5741)
19. Keep tests focused, cheap and deterministic. Assert exact values. Merge duplicate tests. (`**/tests/**`, `**/*tests.rs`; 20 PRs, 5 maintainers) "One is enough, and will take less CPU" [#8188](https://github.com/sigp/lighthouse/pull/8188)
20. Keep flags, config fields and disk formats backward compatible. Deprecate with warnings. (`**/cli.rs`, `**/config.rs`, `beacon_node/store/**`; 18 PRs, 7 maintainers) "Lets put a deprecation warning log here too" [#4920](https://github.com/sigp/lighthouse/pull/4920)
21. Add metrics, timers or tracing spans for costly, rare or failing paths. (`**/*.rs`; 17 PRs, 3 maintainers) "We need to metric time this conversion" [#6475](https://github.com/sigp/lighthouse/pull/6475)
22. Follow the consensus and beacon-API specs exactly. Match spec names and link them. (`consensus/**`, `beacon_node/**`; 16 PRs, 7 maintainers) "Where is this formula from?" [#7347](https://github.com/sigp/lighthouse/pull/7347)
23. Hold locks briefly. Don't block async tasks; use `spawn_blocking`. (`**/*.rs`; 16 PRs, 5 maintainers) "Need a `spawn_blocking` here as well." [#7098](https://github.com/sigp/lighthouse/pull/7098)
24. Penalize peers only for their own fault, with fitting severity. (`beacon_node/network/**`, `beacon_node/lighthouse_network/**`; 16 PRs, 5 maintainers) "Why is this not attributed to block peer?" [#7352](https://github.com/sigp/lighthouse/pull/7352)
25. Make fork code and tests cover the newest fork, such as Gloas. (`**/*.rs`; 14 PRs, 6 maintainers) "Reminder: will need to add gloas support" [#8314](https://github.com/sigp/lighthouse/pull/8314)
